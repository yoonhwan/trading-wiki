작성일: 2026-02-16

카테고리: #LangGraph #RAG #Tutorial #LangChain #AgentSkills

프로젝트 경로: ~/Work/news-links-bot/

📌 개요

Obsidian News-Links/ 폴더의 마크다운 문서들을 벡터 검색 + LLM으로 질의응답하는 RAG 챗봇을 만든다.

핵심 규칙: 코드는 직접 쓰지 않는다. Agent Skills가 가이드하고, 스킬이 제안하는 패턴을 보고 구현한다.

📄 Phase 2: 문서 로더 구현

⚠️ 스킬 없음 — 이 부분은 프로젝트 고유 로직이라 직접 구현한다.

Claude Code에서 이렇게 요청한다:

"src/indexer.py를 만들어줘. 다음 요구사항:
1. VAULT_PATH/News-Links/ 폴더의 모든 .md 파일을 재귀적으로 로드
2. 각 파일에서 H1 제목, 해시태그, 날짜를 메타데이터로 추출
3. RecursiveCharacterTextSplitter로 청킹 (chunk_size=1000, overlap=200)
4. separators는 마크다운 구조 우선: ["\n## ", "\n### ", "\n---\n", "\n\n", "\n"]
5. ChromaDB에 OpenAI text-embedding-3-small로 벡터 저장
6. get_vectorstore() — 기존 DB 있으면 로드, 없으면 새로 생성
7. main으로 직접 실행 가능하게"

🧩 Phase 3: State 설계

🎯 스킬 호출

/langgraph-state-management

스킬이 로드되면 이렇게 말한다:

"RAG Q&A 봇의 State를 설계해줘. 추적해야 할 데이터:
1. 대화 히스토리 — 멀티턴 대화 지원 (누적)
2. 검색된 문서 내용 — 현재 턴의 검색 결과 (매번 덮어쓰기)
3. 출처 파일명 — 답변에 사용된 소스 표시용 (매번 덮어쓰기)
4. 관련성 점수 — 검색 결과 품질 판단 기준, 0.0~1.0 (매번 덮어쓰기)
TypedDict 기반으로, 대화 히스토리는 add_messages 리듀서를 써줘."

개념배우는 것

스킬이 알려주지 않는 것

스킬은 패턴을 제안한다. 우리 프로젝트에 맞는 필드 이름과 타입은 내가 결정:

  • context: list[str] — 검색된 청크 텍스트
  • source_files: list[str] — 출처 파일명
  • confidence_score: float — 그레이딩 결과

🔗 Phase 4: 그래프 구현

🎯 스킬 활용 (간접)

Phase 3에서 State 스킬이 알려준 패턴을 바탕으로 그래프를 구성한다.

Claude Code에서 이렇게 요청한다:

"src/graph.py를 만들어줘. 다음 설계:
노드 3개:
- retrieve — vectorstore.asretriever(k=4)로 검색, context와 sourcefiles 반환
- grade — 각 문서의 관련성을 LLM으로 yes/no 판단, confidence_score 계산
- generate — context 기반 LLM 답변 생성, 출처 파일명 포함
조건부 엣지:
- grade 후 confidence_score >= 0.5 → generate
- grade 후 confidencescore < 0.5 → regeneratequery → retrieve (재검색)
추가 노드:
- regenerate_query — 원래 질문을 LLM으로 재구성
모델: ChatOpenAI(model="gpt-4o-mini", temperature=0)
State: src/state.py의 GraphState 사용
벡터스토어: src/indexer.py의 get_vectorstore() 사용"

그래프 흐름도

START → retrieve → grade ──YES──→ generate → END
                     │
                     NO
                     ↓
              regenerate_query
                     │
                     └──→ retrieve (루프)

🛡️ Phase 5: 에러 핸들링

🎯 스킬 호출

/langgraph-error-handling

스킬이 로드되면 이렇게 말한다:

"Phase 4에서 만든 src/graph.py에 에러 핸들링을 추가해줘.
처리해야 할 에러 시나리오:
1. OpenAI API 일시적 장애 (rate limit, timeout) → 재시도
2. 검색 결과 빈 배열 → 폴백 메시지
3. 벡터 스토어 미존재 → 자동 생성 (이미 indexer에 구현됨)
요청:
- grade, generate, regenerate_query 노드에 RetryPolicy 적용 (3회, 지수 백오프)
- generate에 context 비었을 때 친절한 폴백 메시지 추가"

스킬에서 배울 내용

개념배우는 것
에러 분류Transient vs Recoverable vs User-fixable
RetryPolicymaxattempts, backofffactor 설정법
폴백 패턴그래프 내에서 우아한 실패 처리
Human-in-the-loopinterrupt()/resume() (이번엔 맛보기만)
